# HPFT：DPU 边缘的虚拟队列公平

本章描述 HPFT 的设计。§1 给出模型、目标，以及现有机制为什么给不出这个目标；§2 是设计总览与一条贯穿全文的结构性质；§3–§6 依次是四个部件——把缺失的拥塞信号造出来、把公平算成一个显式的量、把它跟踪上去、在租户自己的拥塞控制之下把它执行掉；§7 论证系统性质并给出边界。

## 1 问题

### 1.1 模型与目标

考虑一朵公有云，租户虚拟机同时产生 TCP 与 RDMA（RoCEv2，lossy，无 PFC）流量并共享同一张网络。运营商要在这张网上同时提供两层保障。**租户间是硬隔离**：每个租户 $i$ 购买一份带宽上限 $MaxRate_i$，同一瓶颈上与他人竞争时按运营商配置的权重 $W_i$ 分配。**租户内是软隔离**：TCP 与 RDMA 按租户自己配置的类权重分享该租户的份额，一类空闲时另一类可以借用，需求回归时归还。

把两层合起来，目标是一个**层级加权 max-min 分配**：以瓶颈容量为根，按租户权重与上限分给各租户，再在租户内按类权重分给两类，每一层都遵循 max-min 的借用语义——要得比自己份额少的只拿他要的那么多，省下的按权重再分给还没满足的人。

两条约束定义了解空间。**租户透明**：不能修改租户的协议栈、拥塞控制或应用。**零数据面改动**：不能依赖交换机改造、新报文格式或额外的信令平面。这两条不是偏好，是公有云的现实——运营商不拥有租户的软件栈，也很少能为一个功能重新采购整张 fabric。

### 1.2 为什么现有机制给不出

障碍有两个，缺一不可地同时存在。

**其一，异构拥塞控制的碰撞不携带政策语义。** TCP 以 RTT 为周期响应丢包，RDMA 的 DCQCN 以亚毫秒响应 ECN，两者听的是不同的信号。共享一个瓶颈队列时，交换机的 ECN 标记只落在 RoCE 报文上，而不开 ECN 的 TCP 把队列养在标记带之上——唯一听信号的那一类被自己的合规性饿死。我们在一个流总数恒定、只改变两类比例的 incast 实验中观察到：只要 TCP 不止一条流，RDMA 类的合计吞吐就被压到瓶颈容量的 2% 以下，且与两类的流数比例几乎无关；更换 RDMA 的重传算法无效，把交换机的 ECN 阈值扫 16 倍、把 DCQCN 的恢复参数扫 30 倍，也翻不了盘。"谁拿多少"是两套算法碰撞的副产品，任何一侧的参数调优都不能把它对齐到运营商的权重意图。

把两类分进不同的交换机流量类（以 DWRR 配类权重）只医好一半。同一实验的 TC 臂里，**类间** 50:50 精确成立——但**租户间**，独占 TCP 类的那个租户拿到等权份额的 2 倍，挤在 RDMA 类里的三个租户各拿 0.65 倍，四个等权租户之间 3 倍的结构性不公在每个比例点上原样存在。这不是调度器的缺陷，是表达力的天花板：TC 只有"类权重"一个旋钮，写不出"每租户一份、租户内两类共享"这样的两层意图，而且流量类的数量（通常 8 个）与租户数不成比例。

**其二，政策瓶颈物理上不产生拥塞信号。** 一个 VM 被政策允许 20G，而它所在的物理链路是 100G 且空闲——超出 20G 的流量不会遇到队列、不会被标记、不会丢包。没有任何信号可供任何拥塞控制响应。政策份额的争夺对传输层根本不可见。第一个障碍说的是"信号存在但没有政策含义"，第二个说的是"信号根本不存在"。

### 1.3 保证范围

HPFT 的保证针对**边缘瓶颈**——有明确属主、且属主能看见其上全部竞争流量的瓶颈。发送端上行链路的属主是发送方；一个 dst VM 的政策份额、以及接收端下行链路，属主是接收方（N 打 1 的 incast 真正形成拥塞的地点，就是最后一跳朝向本机的那个口）。这三类瓶颈有一个共同的物理事实：全部竞争流量都流经同一块 DPU。

在这三类瓶颈上，我们保证稳态分配收敛到 §1.1 定义的层级加权 max-min 份额。**不保证**核心网内部的公平（那里的瓶颈没有一个能看见全部竞争者的属主，扩展路径见 §7.3）、host 内部资源（PCIe、内存带宽）、丢包消除、路径负载均衡，以及亚控制周期的突发精度——短于一个控制周期的突发由租户自己的拥塞控制兜底，它始终运行在我们的整形之下。

## 2 设计总览

### 2.1 三个想法

HPFT 可以概括成一句话：**份额在看得见全部竞争的地方算出来，目标发下去，所有发送端跑同一条规则。**展开是三个想法。

**份额直接算，不去搜索。** 边缘瓶颈的那条物理事实——全部竞争流量经过同一块 DPU——意味着竞争各方尽收眼底。既然如此，就不需要探测、不需要从拥塞信号里推断自己该拿多少：这块 DPU 每个周期把政策（权重、上限、类权重）代入一次层级 water-filling，直接算出每个流集合此刻应得的份额。

**缺失的信号用记账造出来。** 政策瓶颈不排队、不丢包，但可以记账：给每个流集合一个只存在于账本里的虚拟队列，对"到达速率 − 应得份额"做时间积分。持续超出份额的流集合积累欠账、被打上标记。在账本面前，"20G 的政策额度被超出"和"100G 的物理端口被 incast 打满"是同一件事——都是账本超载。§1.2 的第二个障碍就此消除。

**所有发送端对同一个目标跑同一条无权重的规则。** 属主把政策裁定与账本审计压缩成一个目标速率发下去，发送端只把自己的速率平滑地跟踪上去。规则里没有权重、不区分类别——权重在算份额的时候已经用掉了。于是 TCP 与 RDMA 被同一只手整形，各自的拥塞控制照常运行在整形之下；共享瓶颈上"谁拿多少"不再是两套拥塞控制碰撞的副产品。第一个障碍随之消除。

多瓶颈的情形不需要额外机制。一条流途经的每个瓶颈独立记账、独立表达约束：接收端的约束以目标的形式到达，发送端的约束是本地算出的份额，执行时取各瓶颈裁定值中的最小者，最紧的那个自动生效。系统从头到尾不需要比较两端的权重——两端各自归一化，本来就不可比。

对后文最重要的结构性质也在这里：**公平住在目标里，不住在规则里。** 份额由属主显式算出、连同审计折扣压缩成目标广播出去，发送端不必"搜索"公平点，只需把速率跟踪到目标上。这一点直接决定了跟踪规则的选型（§5.1）。

### 2.2 控制环

设控制周期为 $T$。一圈是四步：属主 DPU 逐流集合测量到达速率 $r_f$；把政策代入层级 water-filling，算出应得速率 $e_f$ 与公平上限 $\hat e_f$；用虚拟队列积分超额、审计出标记 $s_f$，压缩成目标 $u_f = \hat e_f(1-\gamma s_f)$；目标随遥测回到发送端，发送端把速率上限 $R_f$ 向 $u_f$ 跟踪一步，执行 $pace_f=\min(R_f, Tree_f)$，下一周期的 $r_f$ 反映效果。

遥测环路本身只有一两个周期，但决定整定的不是它，而是**有效滞后** $\tau_{\rm eff}$——目标是在"兄弟保持现状"的假设下算出的，它从被测量到被执行之间经过测量窗、遥测往返与执行合并。$\tau_{\rm eff}$ 比 $T$ 大一个量级，跟踪的时间常数必须覆盖它（§5.3）。

### 2.3 公平的粒度等于执行的粒度

系统测量、分配、标记、限速的最小单位是**流集合** $f$：三元组 (src VM, dst VM, class)，class ∈ {TCP, RDMA}。这个选择有两个方向上的理由，两个方向都是必要的。

**不能更粗。** 假设只按 VM 对控制，一个 VM 对的 TCP 与 RDMA 共享一个速率上限。任何 pace 执行器都只能约束边界上的总量，不能仲裁边界内部的构成：两类在这个上限之内各拿多少，仍然由两套拥塞控制在执行器的队列上碰撞决定。而执行器采取哪种纪律都有偏袒——丢包偏袒 TCP（RDMA 以重传风暴收场）、打 ECN 偏袒 TCP（TCP 未开 ECN 时只有 RDMA 减速）、背压偏袒 RDMA（硬件直发的流量感受不到背压）。§1.2 的碰撞只是从交换机搬进了执行器，没有被解决。一句话：**要类间公平，测量、分配、执行三者都必须落在 (流对, 类) 上。**

**不必更细。** (src VM, dst VM, class) 已经是政策的最细语义单位：租户权重作用于 VM，类权重作用于类，per-sender 权重作用于来源，再细的粒度（每连接、每 QP）不承载任何政策语义。它还带来两个性质：状态规模是 $O(\text{VM 对} \times 2)$，与租户开多少连接无关；份额按流集合裁定，**租户多开流不多得**——一个 1024 QP 的流集合与一个单 QP 的流集合分得同样的份额，执行面负责在集合内部把它切开（§6.3）。把控制单位定在这里，天然免疫开流数博弈。

### 2.4 继承与重造

控制骨架有清晰的谱系：边缘仲裁、接收端测量加发送端执行、显式反馈、headroom，都可以追溯到 EyeQ 一系的边缘带宽保障系统；用虚拟队列制造信号承自 HULL 的 phantom queue 与 AVQ 的积分标记。骨架是成熟的，我们直接沿用。

新的部分，是这个骨架在"两类各自带着拥塞控制的流量 + 硬件执行"的世界里必须重造的三个部件。其一，公平的单位必须从 VM 或流对细化到 (流对, 类)，否则类间碰撞只是换了个地方发生（§2.3）。其二，EyeQ 一系用"活跃者按保底权重分账"绕开了需求估计——这对保底带宽是够的，而加权 max-min 加借用加超卖的政策目标要求需求的**程度**进入分配，需求估计从此不可回避（§4.1）。其三，EyeQ 式的控制环假设执行器无滞后、被控流量被动服从（软件令牌桶即写即生效，TCP 被 qdisc 背压直接钳住），而租户透明的 RDMA pacing 在任何实现里都是一个自带"量测→施加"滞后的内环控制器，其下还有一到两套活跃的租户拥塞控制。积分审计（§3）、时滞匹配的一阶跟踪律（§5.2）、以及与租户 CC 的耦合（§6.2），都是"被控对象自身有动力学"这一事实的后果。

## 3 把缺失的信号造出来

政策瓶颈不产生拥塞信号（§1.2），所以我们合成一个。每个流集合配一个**虚拟队列**——只存在于账本里的队列，没有任何真实报文在其中排队：

$$vq_f \leftarrow \mathrm{clip}\big(vq_f + \Delta_f\, T,\ 0,\ V\big), \qquad s_f = \min(vq_f / V,\ 1)$$

$$\Delta_f = \begin{cases}
r_f - e_f & r_f > e_f & \text{充入：按真实超额}\\
-(\hat e_f - r_f) & 0 < r_f \le e_f & \text{排空：按未用的公平上限}\\
-V/T & r_f = 0 & \text{空闲：一拍清零}
\end{cases}$$

标记 $s_f \in [0,1]$ 度量"该流集合持续超出应得份额的程度"。三条规则各有一个不可替换的理由。

**充入用积分，不用瞬时比值。** 只有持续的超额才该报警，单个周期的测量毛刺应当被积分吸收。满刻度 $V$ 是一个**墙钟积分量**（超额乘以时间），因此不随控制周期缩放：同样一段超额历史，切成 50 个 $T$ 还是切成 1 个 $50T$，积出来的账相同。$V$ 不是一个拍出来的经验值，它由审计环的目标阻尼反解——审计环（账本积分加比例折扣）线性化之后是标准二阶系统，阻尼比 $\zeta = \frac12\sqrt{kV/(\gamma\hat e^*)}$，取经典最优阻尼 $\zeta = 1/\sqrt2$ 就唯一确定了

$$V = \frac{4\zeta^2\gamma\,\hat e^*}{k},$$

其中 $\hat e^*$ 是典型竞争工作点上的公平上限。这里有一个容易做错的选择：$\hat e^*$ 随**瓶颈容量**缩放，所以 $V$ 必须锚在瓶颈容量上，而不是网卡端口的线速上——锚错了，换一档瓶颈速率阻尼就悄悄变了。积分上限取 $V$ 本身而不更深：更深的积分仓只会让超额停止之后标记多响几拍、加深下冲。

**排空必须按公平上限 $\hat e_f$，不能按应得速率 $e_f$。** 这一条是死锁与不死锁的区别。$e_f$ 被需求估计封顶，而需求又由实测速率折算（§4.1）——一条被深度压制的流，$r_f$ 塌到哪里 $e_f$ 就跟到哪里，排空速度永远只有实际速率的一个小比例，积得深的账排不空，审计信号永久卡满，流被无限期扣着最大折扣，标记也就失去了区分度。换成 $\hat e_f$ 之后，"没用掉的份额"才是排空速度：被压制的流未用份额大、标记迅速被清掉；把份额用满的流（$r_f \approx \hat e_f$）排空趋于零，不会白白被解除标记。

**不发包的流一拍清零。** 一条不发包的流既不充入、也无从按份额排空，队列会冻结在旧值上。让它快速清零，是因为一条放弃了自己拥塞主张的流，不该在恢复发包时继续被基础设施的陈旧状态惩罚。

三类原本互不相同的场景，在这一个机制里被统一。**政策份额争夺**：VM 层的上限使超额流集合 $r_f > e_f$，账本合成出物理上不存在的稀缺性。**incast**：到达总量超出根容量，短缺按权重分摊到各个 $e_f$，而 headroom（账本容量刻意低于物理容量的那一点余量）保证虚拟队列先于交换机的物理队列报警——信号到达发送端时，物理队列还没有形成。**借用与回收**：类层的 work-conserving 是 water-filling 的直接产物，借用的那一类在出借方需求回归、份额被重划之后由标记压回，不需要任何显式协议。

## 4 把公平算成一个显式的量

属主每个周期把政策编译成一个数：目标速率 $u_f$。这一节是编译过程。

### 4.1 需求为什么绕不开

加权 max-min 的定义里就含着"想要多少"。把容量按权重注给各方，谁要得比自己的份额少就只给他要的那么多，省下的按权重再分给还没满足的人——加粗的那一句就是借用，而它是关于需求的判断。举例：容量 $C$、四个等权租户，若都想要很多则各 $C/4$；若其中一个只想要 $0.05C$，max-min 的答案是它拿 $0.05C$、其余三个各拿 $0.317C$。要得出这个答案，分配器**必须**知道"它只想要 $0.05C$"。完全不看需求（只按权重分账，这是保底带宽系统的做法）的答案永远是各 $C/4$——近 20% 的容量闲置，而三个租户正饿着。

难点在于需求不可直接观测。能测的只有到达速率 $r_f$，而 $r_f$ 被系统自己给这条流的限速封顶——一条被压制的流看上去"需求很小"，这是循环论证。基础估计因此取一个试涨额度

$$D_f = r_f\,(1+\delta),$$

即比当前用量高出 $\delta$（本文实现取 15%）。用得掉，下个周期的估计再涨 $\delta$，几个周期就翻倍（$1.15^5 \approx 2$）——爬升是几何的，并不慢；用不掉，估计原地不动，多出来的份额被兄弟借走。$\delta$ 只能小：分配是零和的，给一条流而它当期用不掉的那一部分，正是从兄弟流实际能用的份额里扣出来的。

### 4.2 掉得快、爬得慢，以及积压判别

$r_f$ 是有噪声的：TCP 的一次丢包恢复、RDMA 的一段突发间隙、测量本身的抖动，都会让某一拍的 $r_f$ 掉下去。而 $D_f = r_f(1+\delta)$ 对下掉是**即时**跟随的，对回升却只能一级一级爬 $\delta$——**掉下去一步到位，爬回来要好几拍**。在类层，这个不对称立刻变成兄弟类的实得：某一拍 TCP 因一次丢包恢复少跑了，分配就判定"TCP 想要的比份额少"，把差额划给 RDMA；RDMA 是积压的，立刻用满；下一拍 TCP 想涨回去，却只能从塌下去的值起步爬，期间再抖一次又从头开始。长期平均下来，抖动更多的那一类系统性地低于自己的政策权重——**不是因为它不想要，而是因为需求估计把"一时没跑出来"误读成了"不想要"。**

修正是给需求估计加一道**积压判别**，判据只有一条：从根到叶，只要 $f$ 经过的任何一个节点上实测总量已经贴住该节点的容量，就认定 $f$ 处在竞争中，把它的需求置为根容量——一个大于任何节点份额的**有限**值，在每一层都足以让需求上限失效，等效于无穷。这条判据只用**总量**，而总量是精确测量出来的（§6.4 会说明为什么这一点重要）；判别带滞回，逐节点各自持有，避免在阈值附近抖动。

### 4.3 层级 water-filling 与两个输出

政策是一棵三层的树：根是瓶颈容量（乘上 headroom 之后的账本容量 $C'$），第一层按租户权重 $W_i$ 与上限 $MaxRate_i$ 分给各 dst VM，第二层按类权重分给 TCP 与 RDMA，第三层按 per-sender 权重分给各个发送方。每一层都是一次加权 water-filling：找水位 $t^*$ 使 $\sum_j \min(c_j, w_j t^*) = C$，则子节点 $j$ 得 $e_j = \min(c_j, w_j t^*)$，其中 $c_j$ 是它的需求或上限。

这一步同时产出**两个**量，它们的区别是后文反复用到的。**应得速率** $e_f$ 是"按各方当前需求，$f$ 此刻应得多少"。**公平上限** $\hat e_f$ 是"把 $f$ 的需求设为无穷、兄弟保持实际需求时，$f$ 能分到多少"——它是 $f$ 的份额天花板，恒有 $\hat e_f \ge e_f$。$e_f$ 是分配的结果，$\hat e_f$ 是政策允许的额度；账本的排空按后者（§3），目标的锚也是后者（§4.4）。

两个量可以在同一遍里算出来：每个节点排一次序、建一次前缀和，此后该节点上的一切都是这张表上的二分查询——一次查出普通水位给出全部 $e$，每个子节点各一次查出"换掉它的上限之后"的水位给出它的 $\hat e$。三层沿着 $f$ 从根到叶的那条路径级联，同一祖先下的叶子共用上层结果。总代价是 $O(N\log N)$（$N$ 为活跃流集合数），而不是朴素做法的 $N$ 遍完整分配。

### 4.4 目标合成

属主把对每个流集合的全部裁定压缩成**一个数**：

$$u_f = \hat e_f\,(1 - \gamma\, s_f).$$

$\hat e_f$ 是政策裁定的份额天花板，$s_f$ 是账本审计出的持续超额，$\gamma$ 是审计折扣的力度上限（本文取 0.25）。无超额时目标就是公平上限；持续超额把目标最多压到 $(1-\gamma)\hat e_f$——**审计剂量有界**，而且以折扣的方式进入目标，不是跳变。

锚必须是 $\hat e_f$ 而不是 $e_f$，理由与 §3 排空参照的理由同源：$e_f$ 随流自己的速率塌陷，用它做锚会重演那个自引用陷阱。而锚在"需求置无穷"的 $\hat e_f$ 上并不会多给——$R_f$ 是上限不是授予，需求有限的流把上限垫高也不会多发一个字节，账本只看实测 $r_f$，用不掉的份额照常被借走。

遥测每周期向每个发送端发一条数据报，每个活跃流集合两个数 $\{u_f, r_f\}$。$u_f$ 驱动跟踪律；$r_f$ 是属主实测的到达率，发送端用它作本地树的需求输入、并转发给执行面作反馈。两个协议性设计值得点出：**记录本身就是"新鲜且获准"的显式许可**——$u_f$ 每周期必发（包括无超额时），发送端的一切动作以收到它为前提，遥测断流时系统自动落入 fail-open（§5.4）；**"在报告中"由流表键的存在决定，而不由瞬时速率决定**——一条被限速的流在毫秒尺度上会出现零速率的空拍，若因此漏发记录，发送端会把空拍误判为断流，反过来把系统推进 fail-open。

## 5 跟踪一个已知的设定点

### 5.1 问题重构

经典拥塞控制里，发送端不知道自己的公平份额，所以规则必须自带"向公平收敛"的动力学——增减骨架（AIMD 一族）的全部复杂性都源于此。HPFT 不是这个设定：份额由属主显式算出、连同审计折扣压缩成目标 $u_f$ 每周期广播。发送端要做的只剩一件事——把速率上限 $R_f$ 快速、稳定、无过冲地跟踪到一个**外部已知但滞后**的目标上。

Chiu–Jain 关于增减骨架公平性的经典分析在这里不适用，因为它的前提被消解了：那套分析假设所有源共享同一个二值反馈，而这里每条流拿到的是属于自己的目标，公平已经编码在目标集合里。判据一换，最优的规则也随之换——不需要任何"搜索公平"的增减动力学，只需要一个对滞后广播目标的低通跟踪器。

### 5.2 律

每个流集合维护一个速率上限 $R_f$，新流集合以本地允许的额度起步（乐观起步：短流不付爬坡税；若落在拥塞资源上，一两个周期内目标就会到达并把它拉回，瞬态超额由租户 CC 的即时反应兜底）。每收到一条遥测，只做一件事——**在对数轴上向目标移动一步**：

$$\dot R_f = k\, R_f \ln\frac{u_f}{R_f} \qquad\Longrightarrow\qquad R_f \leftarrow R_f\left(\frac{u_f}{R_f}\right)^{\,1-e^{-k\Delta t}}$$

律定义在连续时间上（令 $z=\ln R_f$，即 $\dot z = k(\ln u_f - z)$），右边的离散更新是它在**实际经过的间隔** $\Delta t$ 上的精确积分，而不是按标称周期。这个区别是正确性要求而不是精度优化：实现里节拍不会严格均匀，遥测也可能迟到，按实际间隔积分把空洞精确补上；更要紧的是指数 $1-e^{-k\Delta t}$ 恒在 $(0,1)$ 内，所以无论间隔多长都只会向目标收敛、绝不越过——若图省事写成 $k\Delta t$ 去补空洞，一次长中断就会让指数远超 1，把速率推到远超目标的地方。

这是对数坐标下的一阶低通跟踪：无分支、无钳位、只有一个参数 $k$。取对数坐标的理由与全文一致——乘性动力学的自然空间：任意大小的份额有相同的相对步长与相同的收敛墙钟，两类流量共用同一个常数，而规则里没有权重（权重只住在算份额的那一端）。

跟踪形式让三类"需要额外机制去兜底"的问题在结构上不存在。**不需要上限钳位**：跟踪是渐近逼近而不是穿越，$R_f$ 从下方接近 $u_f$ 时步长正比于剩余的对数距离，永远不会越过目标，于是"探测过头 → 信号风暴 → 深砍"这一类失稳没有入口。**不需要下限钳位**：向下同样渐近，且审计剂量本身有界（$u_f \ge (1-\gamma)\hat e_f$），执行最多把流压到公平上限的 $(1-\gamma)$，"持续信号把速率复利压穿目标"在结构上不可能。**不需要防跳变**：目标变化时 $R_f$ 以 $1/k$ 的时间常数平滑跟随，从不跳变。

### 5.3 整定：滞后定上界，阻尼定 $V$

两条整定性质决定了参数怎么取。

**$k$ 的上限来自目标的陈旧性。** 每条流的 $u_f$ 都是在"兄弟保持现状"的假设下算出、且滞后 $\tau_{\rm eff}$ 的值。对数跟踪在远离目标处的绝对爬速有一个自然上界 $x\ln(u/x) \le u/e$，因此全体流的联合爬升不超过 $(k/e)\sum u$——按目标自归一化，**不随流数放大**；陈旧窗内的联合瞬时超冲约 $(k/e)\tau_{\rm eff}$。$k$ 的上限由此定出：$k\,\tau_{\rm eff} \lesssim 0.4$，对应约 15% 的瞬时超冲。要提速，该动的是 $\tau_{\rm eff}$（缩短测量窗或执行合并），不是把 $k$ 调大。

**审计环的阻尼由 $V$ 整定。** 跟踪项 $-kz$ 恰好为"积分账本 + 比例折扣"这个环补上阻尼——没有跟踪项时它是一个零阻尼振荡器。线性化后是标准二阶系统，阻尼比 $\zeta = \frac12\sqrt{kV/(\gamma\hat e_f)}$，于是 $V$ 由目标阻尼反解（§3）。$\gamma$ 同时出现在两处：它是折扣的力度上限，也进入阻尼——把审计剂量做有界的同时，也让残余振荡被限制在 $[(1-\gamma)\hat e_f,\ \hat e_f]$ 这条带内。

### 5.4 本地约束与失效退化

发送端 DPU 是上行链路的属主，所以它在本地再跑一棵同样的 water-filling 树（src VM 的上限与类权重），得到本地份额 $Tree_f$，执行时取 $pace_f = \min(R_f, Tree_f)$——§2.1 的"最紧瓶颈生效"在此落地。$Tree_f$ 取发送端视角的**公平上限**而不是需求封顶值，理由与 §4.4 相同：新流起步与失效退化都要求它是"政策允许的额度"，用需求封顶值会得到"新流 $r=0 \Rightarrow Tree \approx 0$"的自相矛盾。

发送端的政策分两层执行，语义与兜底分离。**硬上限**：per-VM 的 $MaxRate_i$ 由网卡硬件限速器执行，类盲、静态、独立于软件栈——**售卖原则**（任何时刻任何 VM 的发送都不超过它购买的额度，即便其他 VM 空闲）由硬件保证，软件失效不破约。**分配语义**：软件树在硬上限之内按超卖比例缩减、做类间软隔离与借用；两类的执行面挂在同一个发送端代理之下，类间借用就是树的 work-conserving 填充本身，不需要独立的仲裁组件。

跟踪律以收到新鲜目标为前提，因此遥测断流有定义明确的退化路径。某流集合静默超过一个短门限后 $R_f$ 冻结；静默超过一个长门限后，**用同一条跟踪律爬向 $Tree_f$**——只是把目标换成本地允许的额度，不引入第二个速率常数、也不需要额外钳位。语义是：属主或遥测路径故障时，流量退化为只受发送端本地政策约束——租户不被卡死（fail-open），也不会失控（$Tree_f$ 封顶，且租户 CC 仍在）。属主恢复后，第一条目标即恢复受控。

还需要回答"再也不回来"：一个已经结束的流集合不应被永远驱动下去，但**遗忘必须以遥测通道确认存活为前提**，判据是同一发送端的其他流集合仍在收到记录。这个门控不可省——单看一条流集合的记录流，"这条流结束了"与"整条通道死了"完全无法区分，不加区分就遗忘，一次通道故障会让全部流集合同时被遗忘、连同失去 $Tree_f$ 的封顶，正是 fail-open 明令排除的失控；而两者在**聚合**视角下是可区分的：真正的通道故障会让所有流集合同时沉默。遗忘时不释放执行面状态——执行器保留最后一次下发的限速值，被遗忘的流集合仍受其约束，只会更慢不会更快。

## 6 在租户的拥塞控制之下执行

### 6.1 契约

两个执行面（RDMA 与 TCP）服从同一个契约：**pace 只延迟发包、不丢包**，实际发送速率等于"租户 CC 想发的"与 $pace_f$ 中的较小者。租户的拥塞控制照常运行在 pace 之下，两个环不会互相激起振荡——分工按时间尺度切开：**亚周期的突发与 fabric 拥塞归租户 CC**，**周期以上的政策份额归 HPFT**。

契约约束的不只是稳态，还有**转变过程**：执行速率的变化不能剧烈到让被控传输把它当成故障，那在效果上就等于丢包，违背契约的本意。跟踪律自身的输出天然满足这一点（目标以 $1/k$ 的时间常数移动）；需要限幅的是从外部注入的阶跃，典型是运营商的大幅政策下调，它经发送端树直达执行面而不经跟踪。这里的风险是具体的：一次大倍率的下调有让 RDMA 连接进入终态失败的风险，而**同样低的速率稳态运行完全安全**——危险的是跌落的倍率，不是终点速率。因此大幅下调在软件面分几拍走完。这不削弱售卖原则：硬件限速器立即执行新额度，软件面的渐进只影响整形轨迹。

契约还有一条容易被忽略的口径要求：**pace 与测量必须用同一套字节口径**，都按线上字节计（含各层头部与帧间隙）。执行面若按应用或内核视角的字节计费（例如分段卸载的超包只算一份表头、不计帧间隙），而测量读的是网卡线上计数，两者之间就有一个恒定的系统增益误差，直接表现为该类流量稳定超出自己的份额。传感器与执行器口径一致，是闭环没有静态偏差的前提。叠加隧道封装时，这套口径整体平移到**内层**线上字节：测量与两个执行面天然都在内层一侧，闭环仍然自洽，外层封装头的容量代价不进入逐流口径，而是并入 headroom 在根容量上一次性让位——给单个执行面加外层补偿反而会重造两类之间的口径不对称（硬件 pacing 无法计费外层）。

### 6.2 与租户 CC 的耦合

租户透明意味着我们不能修改租户的拥塞控制。于是执行面与一个租户 CC 的全部交互只有三步：**读它到达的速率，把它与政策份额合成，按合成结果整形线路。**在这个约束下，合成器不是一个自由的选择——它由租户 CC 的速率能提供什么、不能提供什么决定。

一个租户 CC 的速率**绝对值对我们没有用**。它是对着链路标定的，而不是对着一个从未被告知的份额标定的；而且它会**越走越低、回不去**：很多 CC 的恢复目标是"自己拥塞前的速率"，于是每砍一次，它下次能回到的地方也跟着变低。取小值的合成 $\min(cc,\ level)$ 把这个毛病整个继承了下来——连续几次砍就把流一路推到接近零，并且压在那里。在与另一类共享的边缘瓶颈上，这个过程是自我维持的——RDMA 让出份额，TCP 扩张进来，把队列一直撑在标记阈值之上，RDMA 每次恢复都在完成之前被再次标记。

速率真正携带的信息是它的**下降**：每一次下降都是那个 CC 自己做出的判断——网络要求它让路。乘性下降是尺度无关的，所以一次砍在换算到新单位之后含义不变。于是合成器这样构造：把 CC 的下降累积成一个**相对政策份额的偏离** $d \in [f, 1]$，整形到

$$rate = d \cdot level,$$

其中 $level$ 是政策份额。**下降原封不动地取自每个 CC**——这一半承载了该 CC 对网络的全部读法：信任哪个信号、反应多重、在什么时间尺度上。**恢复归耦合**，因为恢复需要一个目的地，而只有耦合知道一个：政策份额，$d \to 1$，每步把剩余差距减半。整个过程只读比值，所以采样与该 CC 实际会整形的速率之间无论差着什么常数都会约掉——这正是同一个合成器能服务任意 CC 的原因。一句话：**CC 拥有"减"，耦合拥有"恢复"。**

两半都是必需的，各由一个没有它就失败的 CC 教出来。**把恢复交给 CC 自己的目标，它会一路走低**：一个爬回"拥塞前的自己"的 CC，在每次砍都把那个目标一起拉低的情况下，被一串砍推到零并压住，之后只要队列还被标记就回不来。**把恢复交给 CC 自己的步长，它会饿死——不会一路走低，但也爬不回来**：一个每个 RTT 样本按因子减、按固定小步长加的 CC，在一个被别的类一直撑在延迟目标之上的边缘队列里，减持续到来而加性增永远追不上，流就贴在下界附近。

耦合接管恢复在它有权威的地方是安全的：$d \le 1$ 把每条流限在自己的份额之内，而各份额之和按构造等于根容量，所以把任意多条流同时送回各自的份额，都不可能压垮那个用来计算份额的瓶颈。还有一处必须防的自我驱动：**当流被我们自己的整形卡住时（实发速率约等于已下发的份额），那一次降速不计入** $d$——否则整形导致的降速会被读成拥塞信号，再驱动更深的整形。

$d$ 的下界 $f$ 回答一个不同的问题：**这个信号该不该信。** 判据用属主知道、而 CC 不可能知道的那件事——信号来自的瓶颈是不是我们拥有的。属主把根是否饱和作为一个比特随遥测下发，发送端随预算转给执行面。**边缘瓶颈饱和时**，$f$ 取一个不小的分数：CC 可以表达拥塞，但不得交出自己的份额——因为此刻的稀缺正是我们在裁定的那一份，让 CC 把份额让出去等于让它推翻政策。**边缘瓶颈还有余量时**，标记只可能来自我们既看不见也分不了的地方（fabric 深处），$f$ 取接近零：CC 全权。

这个构造还有一个可核对的推论：**接入一个新的 CC 只需要提供它"减"的规则**，别的都不用。

### 6.3 目标已知时，赋值胜过收敛

执行面把 $pace_f$ 作为**流对预算**下发，设备侧在流对内部除以承载数据的队列数，得到每个队列的水位——**直接赋值，不搜索**。预算是已知的，队列数是已知的，没有任何东西需要靠反馈去逼近。这与 §5.1 是同一条原则：**目标已知时，算出来胜过收敛过去**；执行面不是一个独立的收敛过程，而是把已知的政策目标翻译成硬件参数。

用积分去逼近这个已知值的代价是具体的：它需要步长、截幅、防止无限下挖的地板，以及防止对尚未跟上的测量做积分的整定窗口，而一次大幅降预算会把四者同时激发，形成周期以秒计的极限环。改为赋值之后极限环消失，聚合利用率反而上升——搜索期的欠发一并没有了。

按流对下发、在流对内部除以队列数，正是 §2.3 开流免疫在执行面的兑现：租户多开队列只会把同一份预算切得更细，拿不到更多。这里有一个必须写明的定义细节：**只数承载该流对数据的队列，排除传输层保留的管理队列**——它们端口在即存在、持续产生事件却几乎不带字节，计入之后会各占一份而不使用，交付的预算系统性偏低。这不是某个实现的产物，任何真实部署都有。

政策目标通道与拥塞响应通道的速率差是刻意的设计：预算更新走慢通道（批量合并，且变化幅度小于一个阈值时不重写），拥塞响应留在事件速。**预算必须准静态**——执行器把每一次预算变更都当作"上限改变"处理并重置自己的整定窗口，外环若以毫秒级频率改写预算，内环就永远进不了稳态；合并加迟滞把政策通道量化成执行器能消化的节奏，而政策份额本来就是慢变量，降频无损语义。**下降方向不设速率限制**：目标下移时预算一步到位，对单调的下降这既正确又最快；外环本身已经是平滑的，再给下降加一道斜坡，只会让执行面取代律成为收敛的瓶颈。

### 6.4 测量与估计的溯源

属主发回来的 $r_f$ 不是一个同质的量。每个 dst 的**总量**由硬件计数器精确给出、每拍新鲜；把总量**在多个发送方之间的划分**则是估计，依赖流表字节比，带秒级滞后。后者出错的代价不是精度损失而是定性错误——一个新发送方的字节尚未出现时，它的全部流量会被记到同伴头上。

因此有一条使用规则：**判据可以用总量，凡驱动执行面内环的量必须对划分出错免疫。** 饱和判别（§4.2）只用总量，所以它是精确的；而喂给执行面的 per-sender 速率，在成员尚未全部测到时应改用上一拍的授予额度作先验分摊，而不是用尚不可信的字节比。

### 6.5 两个执行点

**RDMA** 的 pace 落在 DPU 的可编程拥塞控制引擎上，租户透明：预算按流对下发，设备侧按 §6.2 与租户 CC 合成，再按 §6.3 赋值到每个队列。

**TCP** 的 pace 落在发送端 host 的内核里：按流对维护 Earliest Departure Time 令牌，为每个报文盖上离场时戳，由 fq 执行——成熟的 delay-only 整形路径，零拷贝、零丢包。控制环的形态与 RDMA 侧完全一致，仅执行点不同；与租户 CC 的合成也是同一个（读内核 CC 的拥塞窗口折算速率，同一个合成器，落到时戳）。

TCP 侧多一个设计点：**稀疏流旁路**。时延敏感的小流不应为吞吐流的整形付排队税，可以绕开共享的 pacing 直接发出。这里的关键是判据必须**是吞吐流无法满足的**——只看"包间隔大于某个门限"不够：开启分段卸载之后，一条吞吐流表现为"大突发 + 大间隔"，同样能通过这个判据，整形形同虚设。因此判据取三个必要条件的合取：该流确实空闲了一段、这一发确实小（不是卸载超包）、且该流对累计的欠债不超过一个突发额度。前两条排除"伪装成稀疏的吞吐流"，第三条给旁路本身封顶，使大量小流的聚合逃逸也有界。

## 7 性质与边界

### 7.1 均衡分配等于政策份额

单个受控资源上这是"按超额程度区别标记的 AQM 加各源响应律"的经典设定：超出 $e_f$ 的流集合被审计折扣持续压回，低于 $\hat e_f$ 的标记被清掉、目标回升，均衡点 $r_f \approx e_f$，而 water-filling 保证 $e_f$ 等于层级加权 max-min 份额。借用场景不需要额外机制：空闲类需求小，它没用掉的份额被重新分给另一类，进入后者的 $e_f$，借用类的目标无折扣地涨上去；需求回归时份额重划，下移的目标把借用者拉回。多瓶颈下"最紧瓶颈生效"由 $pace = \min(R, Tree)$ 给出——每个瓶颈独立裁定、执行取最小，无需比较两端的权重。

### 7.2 稳定性

主环（跟踪）是一阶低通：无条件稳定、结构性无过冲、无参数悬崖。审计环（账本积分加折扣）线性化后是标准二阶系统，阻尼比可整定（§5.3），而折扣有界使残余振荡被限制在 $[(1-\gamma)\hat e_f,\ \hat e_f]$ 带内。

有两处诚实的软肋。其一，跟踪律没有自带的公平安全网——正确性依赖属主裁定（份额与审计）的质量，目标失真它不会自我纠正。因此测量精度与 fail-open 是关键路径上的部件，不是可选件。其二，$k\tau_{\rm eff}$ 的陈旧性预算与 $\zeta$ 的份额依赖给出了解析的稳定边界，但工作点附近的实测裕度尚未系统测定。

### 7.3 边界

**核心网瓶颈。** 核心网的真实拥塞信号没有政策刻度，那里应改用带权重的响应律（权重由运营商配置），与边缘的合成标记天然分离——合成标记走遥测通道，fabric 信号走实测。机制成立，但不在本文的评估范围内。

**两个可选模式。** 需求侧的"份额保底"（账面份额不随速率下探而缩小，代价是速率临时下探期间的借用也一并没有了）与按类步长（利用率优先，代价是比例漂移）保留给特定 SLA 场景，两者都不是默认。

**已知局限。** 亚控制周期的突发精度不承诺，由租户 CC 兜底；政策的在线变更以控制周期为粒度生效，没有原子的多瓶颈切换；VM 迁移的适配，以及多属主组合（一条流同时受两个属主裁定）的规模验证，留作后续。

## 8 实现

三个部件分别运行在属主 DPU 的 Arm 核、发送端 DPU 的 Arm 核与可编程拥塞控制引擎、以及发送端 host 的内核里。语言分工遵循一条原则：每拍在流集合数组上的算术用 C，I/O、解析、配置与控制流用 Python——三层分配的热路径因此是 C，其余控制面是 Python，两个执行面分别是设备端 C 与 eBPF。分配的纯 Python 实现保留为参照实现，与 C 逐点对拍。政策与参数的唯一真值是一份配置文件，属主按文件变更热加载政策段。控制面的开销在两端各占单核不到十分之一。
