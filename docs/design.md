## 0 术语

| 术语 | 定义 |
|---|---|
| 租户 / VM | 本文语境中租户 = 实例 = 虚拟机，粒度相同 |
| 流集合 $f$ | 三元组 (src VM, dst VM, class) 标识的一组流量，class ∈ {TCP, RDMA}。系统测量、分配、标记、限速的最小单位 |
| 政策 | 运营商与租户配置的分配意图：租户权重 $W_i$、租户带宽上限 $MaxRate_i$、类权重、per-sender 权重（§3.2） |
| 属主 | 一个瓶颈资源的所有者。发送端上行归发送方，接收端下行与 dst VM 份额归接收方 |
| 虚拟队列（VQ） | 只存在于账本里的队列：对"到达速率 − 应得速率"之差做时间积分，无真实报文排队（先例：HULL 的 phantom queue） |
| 应得速率 $e_f$ | 属主政策裁定 $f$ 此刻应得的带宽，由层级 water-filling 算出 |
| 公平上限 $\hat e_f$ | $f$ 的份额天花板：把 $f$ 的需求设为无穷、兄弟保持实际需求时 water-filling 分给它的量。恒有 $\hat e_f \ge e_f$ |
| 标记 $s_f$ | 账本审计出的"$f$ 持续超出应得速率的程度"，取值 $[0,1]$；不直接下发，以折扣形式进入目标（§3.4） |
| 目标速率 $u_f$ | 属主压缩后的单一裁定 $u_f = \hat e_f(1-\gamma s_f)$，随遥测广播，是发送端跟踪的对象（§3.4） |
| 跟踪律 | 发送端把速率上限 $R_f$ 向目标 $u_f$ 做对数一阶跟踪的固定规则（§4.2）；本文亦称响应律 |
| pace | 通过控制发包间隔限制流集合速率；只延迟、不丢包 |
| 树份额 $Tree_f$ | 发送端本地树分给 $f$ 的份额，即发送端上行政策的产物（§4.3） |
| work-conserving | 只要还有未满足的需求，容量不闲置；租户内"一类空闲、另一类可借用"即此性质 |
| headroom | 分配总额刻意低于物理容量的余量（3%），使虚拟队列先于物理队列报警 |
| fail-open | 控制通道故障时退化为"不限速"而非"卡死在限速态" |
| 控制周期 $T$ | 测量→分配→标记→响应一圈的节拍，现行 1 ms |

## 1 问题

### 1.1 目标：两层公平

公有云中，租户 VM 同时产生 TCP 与 RDMA（RoCEv2，lossy，无 PFC）流量，
共享网络。运营商需要同时提供：

- **租户间硬隔离**：每租户有购买的带宽上限 $MaxRate_i$；同一瓶颈上竞争时
  按运营商配置的权重分。
- **租户内类间软隔离**：TCP 与 RDMA 按租户自配的类权重分享租户份额；
  一类空闲时另一类可以借用，需求回归时归还。

### 1.2 为什么现有机制给不出

障碍有两个，缺一不可地共同存在。

**其一，异构拥塞控制的碰撞没有政策语义。** TCP（Cubic 以 RTT 为周期响应
丢包）与 RDMA（DCQCN 毫秒级响应 ECN）听的是不同的信号。共享瓶颈队列上，
交换机的 ECN 标记只落在 RoCE 报文上，不开 ECN 的 TCP 把队列养在标记带
之上——唯一听信号的类被自己的合规性饿死。实测（128 流 incast，流总数
恒定、只变两类比例）：只要 TCP 不止一条流，RDMA 类合计就被压到 100G
瓶颈的 2% 以下，与两类流数比例几乎无关；换重传算法（GBN↔SR）无效，
把 ECN 阈值扫 16 倍、恢复参数扫 30 倍也翻不了盘。"谁拿多少"是两套算法
碰撞的副产品，任何一侧的参数调优都无法把它对齐到运营商的权重意图。

把两类分进不同的交换机 TC 队列（DWRR 类权重）只医好一半：同一实验的
TC 臂里，类间 50:50 精确成立——但租户层面，独占 TCP 类的租户拿到等权
份额的 2 倍，挤在 RDMA 类里的三个租户各拿 0.65 倍，4 个等权租户间 3 倍
的结构性不公在每个比例点原样存在。这不是调度器缺陷，是表达力天花板：
TC 只有"类权重"一个旋钮，写不出 §1.1"每租户一份、租户内两类共享"的
两层意图，且 TC 数量（通常 8 个）与租户数不成比例。

**其二，政策瓶颈物理上不产生拥塞信号。** 一个 VM 被政策允许 20G、物理
链路 100G 且空闲时，超额流量不会遇到队列、ECN 或丢包——没有信号可供任何
拥塞控制响应。政策份额的争夺对传输层是不可见的。

约束条件同样是问题的一部分：**租户透明**（不能改租户协议栈与应用）、
**零数据面改动**（不依赖交换机改造与新报文格式，公有云现实）。

### 1.3 保证范围

HPFT 的公平保证只针对**边缘瓶颈**——有属主、且属主能看见其上全部竞争
流量的瓶颈：

| 瓶颈 | 物理/政策 | 属主 | 机制 |
|---|---|---|---|
| 发送端上行 | 物理 | 发送方 | 发送端树（§4.3） |
| dst VM 政策份额 | 政策 | 接收方 | 虚拟调度器标记（§3.2–3.3） |
| 接收端下行（incast 即此：N 打 1 的失配唯一物化点是最后一跳朝本机的口） | 物理 | 接收方 | 调度器 root 层标记（§3.2） |
| 核心网 | 物理 | 运营商 | **不保证**，扩展见 §9.1 |
| host 内部（PCIe/内存） | 物理 | — | 不保证（PicNIC 范畴） |

**保证**：在三类边缘瓶颈上，稳态分配收敛到政策定义的层级加权 max-min
份额。**非目标**：核心网公平；丢包消除；路径负载均衡；亚控制周期
（< $T$）的突发精度——瞬时突发由租户自己的拥塞控制兜底（DCQCN 的 CNP
响应是亚毫秒级的，始终运行在 pace 之下，§5.1）。

## 2 方法总览

### 2.1 核心思想

HPFT 可以概括成一句话：**份额算出来，目标发下去，所有发送端只跑同一条
跟踪规则。**

**份额在看得见全部竞争的地方直接算出来。** 本设计只管边缘瓶颈（§1.3），
它们有一个共同性质：全部竞争流量都经过同一块 DPU——一台机器发出的流量
都经过它的发送端 DPU，落到一台机器的流量都经过它的接收端 DPU。既然竞争
各方尽收眼底，就不需要探测、不需要推断：这块 DPU 每个周期把政策（权重、
上限）代入 water-filling，直接算出每个流集合此刻应得的份额。

**缺失的拥塞信号用记账造出来。** 政策瓶颈没有队列、不丢包，但可以记账：
每个流集合一个虚拟队列，对"到达速率 − 应得份额"做时间积分，持续超出
份额就积累欠账、被打上标记。在标记面前，"20G 政策额度被顶穿"和"100G
物理端口被 incast 顶穿"是同一件事——都是账本超载。§1.2 的第一个障碍
（政策瓶颈无信号）就此消除。

**所有发送端对目标跑同一条无权重的规则**（即跟踪律，§4）：接收端把
政策裁定与账本审计压缩成一个目标速率发下来，发送端只把速率平滑地跟踪
上去。规则里没有权重、不区分类别——权重在算份额时已经用掉了。于是 TCP 与 RDMA 被同一只手整形（各自
的拥塞控制照常运行在整形之下，§5.1），共享瓶颈上"谁拿多少"不再是两套
拥塞控制碰撞的副产品。§1.2 的第二个障碍也随之消除。

多瓶颈的情形不需要额外机制：一条流途经的每个瓶颈独立记账、独立表达
约束——接收端的约束以目标形式到达，发送端的约束就是本地算出的树份额
——执行速率取各瓶颈裁定值中的最小者，最紧的瓶颈自动生效。系统从头到尾
不需要比较两端的权重（两端各自归一化，本来就不可比）。

对后文最重要的结构性质也在这里：**公平住在目标里，不住在规则里。**
应得份额由接收端显式算出、连同审计折扣压缩成一个目标随遥测广播，发送
端不必"搜索"公平点，只需把速率跟踪到目标上——这一点直接决定了跟踪
规则的选型（§4.1）。

### 2.2 控制环

```
发送端 host            发送端 DPU                          接收端 DPU
┌─────────┐   ┌────────────────────────────┐   wire   ┌─────────────────────────┐
│ 租户 VM  │──▶│ ④ pace_f = min(R_f, Tree_f) │─────────▶│ ① 测量：逐流集合到达率 r_f │
│ (TCP/    │   │    R_f ← 跟踪 u_f      §4.2 │          │ ② 分配：water-filling     │
│  RDMA CC)│   │    Tree_f ← 本地树     §4.3 │          │        → e_f, ê_f    §3.2 │
└─────────┘   └──────────────▲─────────────┘          │ ③ 审计：VQ 积分 → s_f §3.3 │
      ▲            遥测（带内）│                        │    目标 u_f = ê_f(1−γs_f) │
      └── TCP pace ───────────┴────── {f: u_f, r_f} 每周期 ──────────┘        §3.4
```

一圈（周期 $T$ = 1 ms）：接收端 DPU 逐流集合测到达速率 $r_f$（①）→ 三层
water-filling 算出应得速率 $e_f$ 与公平上限 $\hat e_f$（②）→ 虚拟队列
积分超额、审计出 $s_f$、压缩成目标 $u_f$（③）→ 遥测回传发送端 → 发送端
把 $R_f$ 向 $u_f$ 跟踪一步并执行 pace（④）→ 下一周期的 $r_f$ 反映效果。
环路总延迟约 1–2 个周期，跟踪的时间常数覆盖这段滞后（§4.2）。

### 2.3 为什么以流集合为控制单位

(src VM, dst VM, class) 是政策的最细语义单位：租户间权重作用于 VM、类间
权重作用于类、per-sender 权重作用于来源，再细的粒度（每连接、每 QP）
不承载任何政策语义。同时它有两个工程性质：状态规模是 O(VM 对 × 2)，与
租户开多少连接无关；份额按流集合裁定，租户多开流**不多得**——把控制
单位定在这里天然免疫开流数博弈（一个 1024 QP 的流集合与单 QP 的流集合
分得同样的份额，执行面负责在集合内部收敛，§5.2）。

反过来，比流集合更粗的单位——只按 VM 对控制——会让类间公平落空。
任何 pace 执行器都只能约束边界上的总量，不能仲裁边界内部的构成：同一
VM 对的 TCP 与 RDMA 若共享一个速率上限，两类在上限之内各拿多少，仍由
两套拥塞控制在执行器队列上的碰撞决定——执行器丢包则偏袒 TCP（RDMA 以
Go-Back-N 重传风暴收场）、打 ECN 则偏袒 TCP（TCP 未开 ECN 时只有 RDMA
减速）、背压则偏袒 RDMA（硬件直发的流量感受不到背压）：无论哪种纪律，
总有一方听不见。§1.2 的碰撞只是从交换机搬进了执行器，没有被解决。
一句话：**公平的粒度等于执行的粒度**——要类间公平，测量、分配、执行
三者都必须落在 (流对, 类) 上。

### 2.4 与现有工作的关系

本设计的控制骨架有清晰的谱系：边缘仲裁、接收端测量 + 发送端执行、显式
反馈、headroom，都可以追溯到 EyeQ（NSDI'13）一系的边缘带宽保障系统；用
虚拟队列制造信号承自 HULL 的 phantom queue 与 AVQ 的积分标记。骨架是
成熟的，本设计沿用不讳。

新的部分，是这个骨架在"两类各带拥塞控制的流量 + 硬件执行"的世界里必须
重造的三个部件（各自的论证在正文就地给出，此处只汇总）。其一，公平单位
必须从 VM/流对细化到 (流对, 类)，否则类间碰撞只是从交换机搬进执行器
（§2.3）。其二，EyeQ 式分配用"活跃者按保底权重分账"绕开了需求估计——
这对保底带宽足够，而加权 max-min + 借用 + 超卖的政策目标要求需求的
**程度**进入分配，需求估计从此不可回避：§3.2 的需求估计、$e_f/\hat e_f$
双输出与 §3.3 的按公平上限排空都是它的产物。其三，EyeQ 式控制环假设
执行器无滞后、被控流量被动服从（软件令牌桶即写即生效，TCP 被 qdisc
背压直接钳住），而租户透明的 RDMA pacing 在任何实现里都是一个自带
"量测→施加"滞后的内环控制器，其下还有两套活跃的租户 CC——积分审计
（§3.3）、准静态设定点（§5.2）、时滞匹配的一阶跟踪律（§4.2），都是
"被控对象自身有动力学"的后果。

其余近邻各一句：VCC/AC-DC 在 vSwitch 为 TCP 垫统一拥塞控制，不覆盖
RDMA 与政策层级；EQDS 以 credit 准入 + 数据面替换解决共存，本设计是其
rate-based 对偶——零数据面改动、类粒度政策。

## 3 接收端：把政策编译成目标

接收端 DPU 是 dst VM 份额与接收端下行两个瓶颈的属主。它每周期做三件事
——测量、分配、审计——并把裁定压缩成一个目标速率发布出去。

### 3.1 测量：逐流集合到达速率

设计对测量提出三条要求，每条都直接源于控制器的正确性：

1. **粒度与执行面对齐。** 执行面按类限速（RDMA 走硬件 pacing，TCP 走
   host pacing），测量就必须按类计数。若把两类合并计数而执行只能压其中
   一类，控制器会把全部误差倾泻到可控的那一类上，直至把它压穿。
2. **字节与时间戳同源同钟。** 速率是差分量，字节数与时刻一旦来自两个
   时钟域（或采样节拍被其他工作扰动），除法会放大成百分之几十的速率
   噪声，足以淹没标记信号。
3. **新鲜度按用途分级。** 类级总量进入 VQ 积分，必须每周期新鲜；类内
   per-sender 构成比只影响第三层细分，允许秒级滞后。

据此，测量是一条分级混合链：**每 VF 的类级速率**从 NIC 硬件的 vport
计数器直读——RoCE 与内核路径（TCP 等）字节落在两个独立的硬件桶里，
天然给出类拆分，任意采样频率下都新鲜，由 DPU 本地采样进程以本机单调钟
统一打戳；**类内多发送方的构成比**用流表（megaflow）字节计数的滑窗
份额细分。链条逐级失效安全：任何一级数据源变陈旧，就退回下一级，测量
进程可随时死掉而系统不失效。实测精度：与主机侧计数逐字节对账一致，
8 流 incast 稳态误差 0.36%（§8.3）。

### 3.2 分配：三层 water-filling

**贯穿本节的算例。** 接收端下行 100G，headroom 3% ⇒ 账本容量
$C' = 97$G。两个 dst 租户 A、B，权重相同、各购买 $MaxRate$ = 60G。
租户 A 内部有 TCP 与 RDMA 两类，类权重 1:1；租户 B 只有 RDMA。每类
只有一个发送方（第 3 层退化，最后单独说）。

#### 3.2.1 为什么必须估计需求

加权 max-min 的定义里就含着"想要多少"：把容量按权重注给各方，**谁要
得比自己的份额少就只给他要的那么多，省下的按权重再分给还没满足的
人**，如此往复。加粗那句就是借用。

举例：97G、4 个等权租户。若都想要很多，各 24.25G；若其中一个只想要
5G，加权 max-min 的答案是它拿 5G、其余三个各拿 $(97-5)/3 = 30.7$G。
要得出这个答案，分配器**必须**知道"它只想要 5G"。若完全不看需求（只
按权重分账，这是保底带宽系统的做法），答案永远是各 24.25G——19.25G
的容量闲置，而三个租户正饿着。一句话：**借用就是把用不掉的份额分给
用得掉的人，而"用不掉"是关于需求的判断，绕不开。**

难点在于需求不可直接观测：能测的只有到达速率 $r_f$，而 $r_f$ 被系统
自己给这条流的限速封顶——一条被压制的流看上去"需求很小"，这是循环
论证。基础估计因此取

$$D_f = r_f\,(1+\delta), \qquad \delta = 15\%$$

即给每条流一个比它当前用量高 15% 的"试涨额度"。用得掉，下周期估计
再涨 15%，5 个周期就翻倍（$1.15^5 \approx 2.0$，1 ms 周期下即 5 ms）
——爬升是几何的，并不慢；用不掉，估计原地不动，多出的份额被兄弟借走。
$\delta$ 只能小：分配是零和的，给一条流而它当期用不掉的那 15%，正是
从兄弟流实际能用的份额里扣出来的。

#### 3.2.2 棘轮偏差与积压判别

$r_f$ 是有噪声的：TCP 一次丢包恢复、RDMA 一段突发间隙、测量本身的
抖动，都会让某一拍的 $r_f$ 掉下去。而 $D_f = r_f(1+\delta)$ 对下掉是
**即时**跟随的，对回升却要一级一级爬 15%——一个"掉得快、回得慢"的
棘轮。在类层，这个不对称会被兄弟类立刻套现：

> 租户 A 的 48.5G 由 TCP、RDMA 按 1:1 分，两类都满负荷跑、各 24.25G。
> 某一拍 TCP 因一次丢包恢复只跑出 18G：
> - 这一拍 TCP 的类需求 = $ 18 \times 1.15 = 20.7 $ G < 24.25G ⇒ 注水
>   判定"TCP 想要的比份额少"，只给它 20.7G，余下 3.55G 归 RDMA；
> - RDMA 是积压的，立刻把 27.8G 用满；
> - 下一拍 TCP 想涨回去，但需求估计只能从 $ 18 \times 1.15 $ 起步，要
>   2–3 拍才爬回 24.25G——期间再抖一次，又从头开始。

长期平均下来，抖动更多的那一类系统性地低于政策权重（实测中类比例曾
偏到 0.75）：**不是因为它不想要，而是因为需求估计把"一时没跑出来"
误读成了"不想要"。**

修正是给需求估计加一道**积压判别**。先算一个中立的参照量
$\hat s_f$——假如所有流集合都饥渴（需求全部置无穷）时，这棵树按权重
会分给 $f$ 的量，即 $f$ 的**纯权重份额**。全员无穷时唯一还起作用的
约束是各 VM 的 $MaxRate$，所以 $\hat s_f$ **只取决于政策与当前活跃的
流集合，与任何实测速率无关**——尺子本身是稳的，只在成员变动或政策
变更时才变，这正是它能当中立参照的原因。判据：

$$r_f \ge \theta_b\,\hat s_f\ (\theta_b = 0.5)\ \Rightarrow\ f\ \text{积压，}D_f \leftarrow C'$$

积压者的需求置为根容量 $C'$——一个大于任何节点份额的**有限**值，在每
一层都足以让需求上限失效（等效于无穷），但仍是个具体数字，因为由它导出
的 $\hat e_f$ 要作为一个速率广播给发送端（§3.4）。积压者由此主张完整的
权重份额，不再被自己的瞬时速率封顶；未过门限者保持
$D_f = r_f(1+\delta)$。回到上例：TCP 掉到 18G 时
$18 \ge 0.5 \times 24.25$ 成立，它仍被判为积压、照拿 24.25G，兄弟类
借不走——抖动不再被误读为退让。而一条真正空闲的流（例如只用 2G，
远低于半份额）仍按 $r_f(1+\delta)$ 报需求，没用的份额照常出借，借用
机制完好。

两点诚实说明。其一，硬门限在这里不产生抖动或双稳态：判为积压会抬高
份额、抬高份额会抬高 $r_f$，正反馈把流锁在积压态；反过来一条被误判
为空闲的积压流，靠 15%/周期的梯子约 5 拍就能爬过门限，逃逸路径很短。
其二，代价是真实的：一条恰好用掉自己半份额的流会占住整份额度，它没
用掉的部分不再出借。$\theta_b$ 就是"比例保真 ↔ 利用率"的旋钮，0.5
是实测折中；$\theta_b \to 0$ 退化为"份额保底"（比例最准、借用全死），
$\theta_b \to 1$ 退化为无判别（借用最活、比例最飘）。

#### 3.2.3 四个量，各是什么、给谁用

| 量 | 怎么得到 | 谁消费它 |
|---|---|---|
| $D_f$ 需求估计 | $r_f(1+\delta)$；积压者置为大于容量的值 | 分配的**输入** |
| $\hat s_f$ 纯权重份额 | 把**所有**流集合的需求置无穷，跑一遍分配 | **只**用作积压判别的尺子（§3.2.2） |
| $e_f$ 应得速率 | 用 $\{D_f\}$ 跑分配的输出 | 账本充入参照：$r_f > e_f$ 才记账（§3.3） |
| $\hat e_f$ 公平上限 | 只把 **$f$ 自己**的需求置无穷、兄弟保持 $D$，跑分配 | 账本排空参照（§3.3）+ 目标 $u_f$ 的锚（§3.4） |

留意 $\hat s_f$ 与 $\hat e_f$ 的区别：前者是"大家都饥渴"时的份额，
是一把中立的尺子；后者是"只有我饥渴、别人照旧"时的份额，是给这条流
的天花板。两者只在全员积压时相等。

#### 3.2.4 层级分配怎么算

整棵树上跑的是**两趟**：**自下而上聚合需求**（叶子的 $D_f$ 逐层求和，
VM 层再被购买额度削顶：上限 $= \min(MaxRate_d,\ \sum\text{子树需求})$），
然后**自上而下分配容量**（根容量按权重逐层注水下去）。§3.2.2 的
$\hat s_f$ 与本节的 $e_f$ 都是这两趟的产物，区别只在第一趟喂进去的
需求是什么：$\hat s_f$ 喂全员无穷（于是只有 $MaxRate$ 还起作用），
$e_f$ 喂 $\{D_f\}$。

其中"分配"这一趟每个节点上做的是**带上限的加权注水**：想象往一排杯子
里倒水，水位 $t$ 均匀上涨，子节点 $j$ 的取水量是 $w_j\,t$，但不超过它
自己的上限 $c_j$；谁先到上限谁"冻结"，它省下的水继续按权重分给没冻结
的，直到容量注完或全部冻结。三层的容量与上限是：

```
根容量 C' = 下行线速 × (1 − headroom)        ← 线速变化实时跟踪
第 1 层（VM）    ：C' 按租户权重 W_d 分给各 dst VM
                   VM d 的上限 = min(MaxRate_d, 其子树需求和)
第 2 层（类）    ：VM 的份额按类权重分给 {TCP, RDMA}
                   类的上限 = 该类的需求和
第 3 层（流集合）：类的份额按 per-sender 权重 u 分给各 src
                   流集合的上限 = D_f
```

**借用的完整算例。** 租户 A 的 TCP 只想要 5G（$D_{\rm TCP} = 5$ G），
RDMA 积压（$D$ 置大），租户 B 积压：

- **第 1 层**：A 的子树需求和 = 5 + 大 ⇒ 上限 $\min(60,\,\text{大}) =
  60$ G；B 同理。97G 按 1:1 注水，水位涨到 48.5 时容量用尽，两者都没
  碰到 60G 的上限 ⇒ **A、B 各 48.5G**。
- **第 2 层**：A 的 48.5G 在 TCP（权重 1，上限 5）与 RDMA（权重 1，
  上限大）之间注水。水位涨到 5 时 TCP 冻结（拿 5G，此时共用掉 10G），
  余下 38.5G 全部注给 RDMA ⇒ **RDMA 拿 43.5G**，而它的纯权重份额只有
  24.25G——多出的 19.25G 就是从 TCP 借来的。借用不需要任何协议、任何
  显式消息，它**就是注水的余量回灌本身**。
- **第 3 层**：每类只有一个发送方，直接继承上层份额。若同一类有多个
  发送方（多对多），在它们之间按 per-sender 权重重复同样的注水。

**回收。** TCP 需求回到满负荷的那一拍，第 2 层重新注水 ⇒ 两类各
24.25G。RDMA 的 $\hat e$ 从 43.5G 一步降到 24.25G，目标 $u$ 随之下移
（§3.4），跟踪律把它拉回；同时它的到达率 43.5G > $e$ = 24.25G，账本
开始记账、审计折扣追加压力。**回收的主力是份额重划（一拍生效），审计
只是对"赖着不走"的追加惩罚。**

这个算例顺带解释了 §3.3 为什么排空必须用 $\hat e_f$：借用状态下 TCP 的
$e_{\rm TCP}$ 只有 5G，若拿它当排空参照，排空速度 $= e - r = 0$，账本
永远排不空；而 $\hat e_{\rm TCP} = 24.25$ G（下一小节算），排空速度是
19.25G，一拍就清。

#### 3.2.5 公平上限 $\hat e_f$ 与单遍级联

**定义与用途。** $\hat e_f$ 是"把 $f$ 自己的需求换成无穷、兄弟保持
现有需求"时分配给 $f$ 的量，即这条流当下**政策允许的天花板**。上例中
$\hat e_{\rm TCP}$：把 TCP 的需求置无穷后，第 1 层 A 的上限变成
$\min(60,\infty) = 60$ G，A 仍分到 48.5G；第 2 层两类都不受自身需求
封顶，各 24.25G ⇒ $\hat e_{\rm TCP} = 24.25$ G，而 $e_{\rm TCP} = 5$ G。
恒有 $\hat e_f \ge e_f$，全员积压时相等。它的两个消费者是账本排空
（§3.3）与目标的锚（§3.4）——两处都需要一个**不随这条流自己的速率
塌陷**的参照量。

**朴素算法**是对每条流集合把需求换成无穷、重跑一遍整棵树：$N$ 遍
完整分配，代价 $O(N^2)$ 以上。

**单遍级联。** 在任一节点上，注水的水位 $t^*$ 由
$F(t) = \sum_j \min(c_j,\ w_j t) = C$ 决定。$F$ 是分段线性增函数，
折点在 $t_j = c_j/w_j$。把某个子节点 $i$ 的上限换成 $\infty$，只改变
$F$ 里属于 $i$ 的那一项：

$$g_i(t) = F(t) - \min(c_i,\ w_i t) + w_i t$$

仍是同一组折点上的分段线性增函数。于是：把折点排一次序、预存前缀和
（$O(m\log m)$），此后**每个**子节点的新水位都只是在这组折点上二分
一次（$O(\log m)$），其上限即 $w_i t^*_i$。一次排序 + $m$ 次二分，
得到全部 $m$ 个子节点的上限。

三层怎么串起来：把 $f$ 的需求置无穷后，第 1 层里 $f$ 所在 VM 的上限
变成 $\min(MaxRate, \infty) = MaxRate$，第 2 层里 $f$ 所在类的上限变成
$\infty$——两者都正好是"把某个子节点的上限换掉"这一种形式。所以从根
到叶三层各做一次上述单遍计算，把上一层算出的上限当作下一层的容量，
逐层下推即可。

级联沿着 $f$ 那条**从根到叶的路径**走，且同一祖先下的叶子共用上层
结果：第 1 层那次查询的结果被该 VM 下的全部叶子共用，第 2 层的被该类
下的叶子共用。

**"同批"的准确含义。** 每个节点排一次序、建一次前缀和后得到一张表，
此后该节点上的一切都是这张表上的二分查询：**一次**查出普通水位
$t^*$（$F(t^*) = C$）⇒ 全部子节点的 $e = \min(c_j,\ w_j t^*)$；
**每个子节点各一次**查出换掉上限后的水位 ⇒ 全部 $\hat e$。$m$ 个子
节点合计 $m+1$ 次查询，共用同一份排序与前缀和——这才是"同批"，而不是
"算 $e$ 时顺手就有了 $\hat e$"。

**代价。** $N$ 指当前活跃的流集合总数（叶子数）。三层树上各节点的
子节点数之和是 $O(N)$，每个节点 $O(m\log m)$，故一趟同时给出全部
$e_f$ 与 $\hat e_f$ 的总代价是 $O(N\log N)$——对照朴素做法的 $N$ 遍
完整分配（$O(N^2)$ 以上）。实测 20 个流集合一遍 448 µs（§7）。

**headroom = 3%** 使账本容量略低于物理容量，保证 incast 时虚拟队列先于
交换机物理队列报警——信号到达发送端时，物理队列还没有形成。

### 3.3 审计：虚拟队列积分

每流集合一个积分器：

$$vq_f \leftarrow \mathrm{clip}\big(vq_f + \Delta_f\, T,\; 0,\; V\big),
\qquad s_f = \min(vq_f / V,\ 1)$$

$$\Delta_f = \begin{cases}
r_f - e_f & r_f > e_f \quad\text{（充入：按真实超额）}\\[2pt]
-(\hat e_f - r_f) & 0 < r_f \le e_f \quad\text{（排空：按未用的公平上限）}\\[2pt]
-V/T & r_f = 0 \quad\text{（空闲：快排清零）}
\end{cases}$$

三条规则各有一个不可替换的理由。

**充入用积分而非瞬时比值**：只对持续超额报警，单周期的测量毛刺被积分
吸收（AVQ 一脉）。满刻度 $V$ 是一个墙钟积分量（超额 × 时间），因此
**不随控制周期缩放**——同样一段超额历史，不论切成 50 个 1 ms 还是 1 个
50 ms 周期，积出的账相同。$V$ 定为 600 Mbit（= 0.1 s × 线速 × headroom，即约 100 ms 的
headroom 量级持续超额才把标记推到饱和）；积分上限取 $V$ 本身，更深的积分
仓只会让超额停止后标记多响几拍、加深下冲。

**排空必须用 $\hat e_f$，不能用 $e_f$**，否则有死锁：$e_f$ 被需求估计
封顶，而需求由实测速率折算——一条被深度压制的流，$r_f$ 塌到哪里 $e_f$
就跟到哪里，排空速度永远只有实际速率的 15%，深积分排不空、审计信号
永久卡满——流被无限期扣着最大折扣，信号失去区分度（旧形态下这曾表现
为流被永久钉死在地板上，实测复现过）。换成 $\hat e_f$ 后，"没用掉的份额"才是排空速度：
被压制的流未用份额大、快速解标恢复；把份额用满的流（$r_f \approx
\hat e_f$）排空趋于零，不白得解标机会。

**空闲流快排**：不发包的流既不充入也无从按份额排空，队列会冻结在旧值。
让它以每周期 $V$ 的速度清零——一条不再发包的流放弃自己的拥塞主张，
基础设施的陈旧状态不应在应用恢复发包时继续惩罚它（fail-open 精神）。

三类场景在这一个机制里统一：**政策份额争夺**（物理零拥塞）——VM 层
上限使超额流集合 $r_f > e_f$，账本合成出稀缺性；**incast**——root 容量
被顶穿，短缺按权重摊进各 $e_f$，headroom 保证账本先于物理报警；
**借用与回收**——类层 work-conserving 的直接产物，借用类在出借类需求
回归时被重划的 $e_f$ 标记压回，无需任何显式协议。

### 3.4 目标合成与遥测

接收端把对每个流集合的全部裁定压缩成**一个目标速率**：

$$u_f = \hat e_f\,(1 - \gamma\, s_f)$$

$\hat e_f$ 是政策裁定的份额天花板（§3.2），$s_f$ 是账本审计出的持续
超额（§3.3），$\gamma$ = 0.25 是审计折扣的力度上限。无超额时
$u_f = \hat e_f$——目标就是公平上限；持续超额把目标最多压到
$(1-\gamma)\hat e_f$——审计剂量有界，且以折扣而非跳变的方式进入目标。
锚用 $\hat e_f$ 而非 $e_f$ 的理由见 §4.2 末段。

遥测每周期向每个发送端 DPU 发一条数据报，每个活跃流集合**两个数**：
$\{u_f,\ r_f\}$。$u_f$ 驱动跟踪律（§4.2）；$r_f$ 是接收端实测的类级
到达率，发送端把它转发给 RDMA 执行器作速率反馈（§5.2）、并用作发送端
树的需求输入（§4.3）。

两个协议性设计：**记录本身就是"新鲜且获准"的显式许可**——$u_f$ 每
周期必发（包括无超额时），发送端的一切动作以收到它为前提，遥测断流时
系统自动落入 fail-open（§4.4）；
**流集合的"在报告中"由流表键的存在决定，而不由瞬时速率决定**——一个
被限速的流在毫秒尺度上会出现零速率的空拍，若因此漏发记录，发送端会把
空拍误判为断流，正反馈进 fail-open。记录是定长二进制（毫秒周期下编解码
成本必须可忽略）。

遥测与被控数据走同一条物理路径（带内，稳态往返 0.1 ms）：生产环境不
存在独立的管理网，设计不依赖它；路径故障造成的遥测中断由 fail-open
语义接管。

## 4 发送端：统一跟踪律

### 4.1 问题重构：设定点跟踪，不是公平搜索

经典拥塞控制里发送端不知道自己的公平份额，律必须自带"向公平收敛"的
动力学——增减骨架（AIMD 一族）的全部复杂性都源于此。HPFT 不是这个
设定：公平份额由接收端 water-filling 显式算出、连同审计折扣压缩成目标
$u_f$ 每周期广播。发送端要做的只剩一件事——

> 把速率上限 $R_f$ 快速、稳定、无过冲地跟踪到一个外部已知、但滞后
> 1–2 个周期的目标 $u_f$。

Chiu–Jain 关于增减骨架公平性的经典分析在此不适用，因为它的前提（所有
源共享同一个二值反馈）被逐流差分裁定消解了：每条流拿到的是自己的目标，
公平已经编码在目标集合里。判据一换，最优规则随之换：不需要任何"搜索
公平"的增减动力学，只需要一个对滞后广播目标的低通跟踪器——§4.2 就是
这个跟踪器的最小形式。

### 4.2 律

每流集合维护速率上限 $R_f$，新流集合以 $R_f = Tree_f$ 起步（乐观起步：
短流不付爬坡税；若落在拥塞资源上，1–2 周期内目标到达、把它拉回，瞬态
超额由租户 CC 的即时反应兜底）。每收到一条遥测，只做一件事——**在
对数轴上向目标移动一步**：

$$R_f \leftarrow R_f\left(\frac{u_f}{R_f}\right)^{kT}
\qquad\Longleftrightarrow\qquad
\dot R_f = k\, R_f \ln\frac{u_f}{R_f}$$

这是对数坐标下的一阶低通跟踪（令 $z = \ln R_f$，即教科书的
$\dot z = k(\ln u_f - z)$）：无分支、无钳位、单参数 $k$ = 20 s⁻¹
（时间常数 50 ms，进入 5% 带约 $3/k$ = 150 ms）。取对数坐标的理由与
全文一致：乘性动力学的自然空间——任意大小的份额有相同的相对步长与
相同的收敛墙钟，两类流量共用同一常数，律中没有权重（权重只住在算份额
的一端，§2.1）。实现另有一道与律正交的绝对地板（50 Mbps，§6），防
执行器深瘫，不参与律的动力学。

旧形态（增减骨架）需要"墙"来兜底的三个问题，在跟踪形式下不复存在：

**不需要顶。** 跟踪是渐近逼近，不是穿越——$R_f$ 从下方接近 $u_f$ 时
步长正比于剩余的对数距离，永远不会越过目标。"全速爬升 + 硬顶截停"
的天花板钳位由此消失，而"探测过头 → 信号风暴 → 深砍"的失稳家族依旧
结构性不存在（没有任何状态会停留在目标之上）。

**不需要底。** 向下同样渐近；且审计剂量本身有界——$u_f \ge
(1-\gamma)\hat e_f$（§3.4），执行最多把流压到公平上限的 75%，"持续
信号把速率复利压穿目标"在结构上不可能。旧形态的触底钳位、以及它引出
的单调性补丁（流体分析发现一），整族退场。

**不需要防跳变。** 目标变化时 $R_f$ 以 $1/k$ 的时间常数平滑跟随，从不
跳变；"多条流同时跳上互相引用的陈旧天花板"的事故入口（实验证实的
直接跳变失稳）被时间常数本身关闭。

两条整定性质（推导见 `design_theory.md`）：

**$k$ 的上限来自目标的陈旧性。** 每条流的 $u_f$ 都是在"兄弟保持现状"
假设下算出、且滞后 $\tau_{\rm eff}$ ≈ 15–25 ms 的值。对数跟踪在远离
目标处的绝对爬速被 $x\ln(u/x) \le u/e$ 自界（$e$ 为自然常数），全体流
的联合爬升不超过 $(k/e)\sum u$——按目标自归一化，不随流数放大。陈旧性
预算 $k\,\tau_{\rm eff} \lesssim 0.4$，现值在预算之内。

**审计环的阻尼可整定。** 跟踪项 $-k z$ 恰好为"积分账本 + 比例折扣"
这个环补上阻尼（无跟踪项时它是零阻尼振荡器），线性化后是标准二阶系统，
阻尼比 $\zeta = \tfrac12\sqrt{kV/(\gamma\hat e_f)}$：$\gamma$ = 0.25 使
典型份额（10 G 量级）过阻尼；大份额欠阻尼但振荡被折扣带
$[(1-\gamma)\hat e_f,\ \hat e_f]$ 兜住。旧形态靠墙压住振荡，新形态靠
结构阻尼消灭振荡。

目标锚在"需求置无穷"的 $\hat e_f$ 上不会多给：$R_f$ 是上限不是授予，
需求有限的流把上限垫高也不多发一个字节，账本分配只看实测 $r_f$，用
不掉的份额照常 work-conserving 借出（§3.2）。锚也必须是 $\hat e_f$ 而
非需求封顶的 $e_f$——后者随流自己的速率塌陷，会重演 §3.3 排空参照的
自引用陷阱。

### 4.3 发送端树与两层模型

发送端 DPU 是上行链路的属主，同一套 water-filling 在本地再跑一棵树
（src VM 的 $MaxRate$ 与类权重 → $Tree_f$），执行取
$pace_f = \min(R_f,\ Tree_f)$——"最紧瓶颈生效"（§2.1）在此落地：接收端
约束经 $R_f$、发送端约束经 $Tree_f$，紧者生效。树的需求输入用遥测带回的
$r_f$ 加增长余量，外加满载探测：一个把 pace 用到 85% 以上的流集合按
$pace(1+\delta)$ 报需求，表达"还想涨"的胃口。$Tree_f$ 取发送端视角的
公平上限（$f$ 需求置无穷的份额）而非需求封顶值——新流起步（$R_f =
Tree_f$）和 fail-open 回升目标都要求它是"政策允许的额度"：需求封顶下
新流 $r=0 \Rightarrow Tree \approx 0$，自相矛盾。

发送端政策分两层执行，语义与兜底分离：

- **第一层（硬上限）**：per-VM $MaxRate_i$ 由 NIC 硬件限速器执行，
  类盲、静态、独立于软件栈——**售卖原则**（任何时刻任何 VM 的发送不
  超过其购买额度，即便其他 VM 空闲）由硬件保证，软件失效不破约。
- **第二层（分配语义）**：上述软件树在硬上限之内做超售缩水、类间软
  隔离与借用。两个类的执行面（RDMA / TCP）挂在同一个发送端代理下，
  类间借用就是树的 work-conserving 填充本身，不需要独立的仲裁组件。

### 4.4 fail-open

响应律的增速以"新鲜且无拥塞"的遥测为前提（§3.4），因此遥测断流有
明确定义的退化路径：某流集合连续 $N_1$ 个周期（0.25 s）无记录，$R_f$
冻结（不增不减）；连续 $N_2$ 个周期（2 s）后，$R_f$ 以固定斜率爬向
$Tree_f$。语义：接收端 DPU 或遥测路径故障时，流量退化为只受发送端本地
政策约束——租户不被卡死（fail-open），也不会失控（$Tree_f$ 封顶，且
租户 CC 仍在）。接收端恢复后，第一条标记即恢复受控。

## 5 执行面

### 5.1 契约与双环分工

两个执行面服从同一契约：**pace 只延迟发包、不丢包**，实际发送速率 =
min(租户 CC 想发的, $pace_f$)。租户的拥塞控制照常运行在 pace 之下，
两环不会互相激振：对租户 TCP，pace 表现为一条平滑的管道（OnRamp 同型
论证）；对 RDMA，min(DCQCN, budget) 的组合在本测试床长期运行验证。
分工按时间尺度切开——**亚周期的突发与 fabric 拥塞归租户 CC**（CNP
响应亚毫秒级），**周期以上的政策份额归 HPFT**。

### 5.2 RDMA：流对预算的水位控制

RDMA 的 pace 落到 DPU 可编程拥塞控制（PCC）引擎上，租户透明。发送端
代理把 $pace_f$ 作为**流对预算**下发；设备侧为每个流对维护一个水位
$level$，对流对内**每个 QP** 施加 rate = min($cc$, $level$)，并用测得的
流对聚合速率做闭环：聚合超预算则按比例压水位，低于预算则小步抬升。
水位控制的要点是 **O(1) 状态、不数流**：均衡水位自动落在 budget/N，
任意 QP 数下聚合都收敛到预算——这是 §2.3 开流免疫在执行面的兑现（防
挖穿的保护地板同样必须钳在聚合速率上而非每 QP 速率上，否则地板 × N
就是逃逸通道）。速率反馈优先用遥测带回的接收端实测值：它与标记同源，
且不受发送侧事件采样丢失的影响。

$cc$ 项是设备侧自实现的 DCQCN 风味状态机（CNP 到达按 QP 数归一化地
乘性减、周期性加性恢复），作为 fabric 拥塞的事件速兜底，与政策水位
正交（16–256 流下自身公平 0.98–0.99）。

政策目标通道与拥塞响应通道的速率差是刻意的设计：预算更新走慢通道
（设备邮箱毫秒级每批，代理端合并到约 13 ms 一次，且变化幅度小于 3%
时不重写），拥塞响应留在事件速。**预算必须准静态**——执行器把每一次
预算变更都当作"上限改变"处理并重置自己的整定窗口，外环若以毫秒级
频率改写预算，内环就永远进不了稳态；合并 + 迟滞把政策通道量化成执行器
能消化的节奏，而政策份额本来就是慢变量，降频无损语义。

**下降方向不设速率限制。** 目标下移时预算一步到位，执行器用比例前馈
（水位按新旧预算之比缩放）在一步内跟上——对单调的下降，这既正确又最快。
外环本身已经是平滑的（跟踪律以 $1/k$ 的时间常数移动，§4.2），不会出现
需要额外阻尼的高频往复；再给下降加一道斜坡，只会让执行面取代律成为
收敛的瓶颈，把律的降速能力白白钳掉。

### 5.3 TCP：host 侧 EDT pacing

TCP 的 pace 落在发送端 host 内核：eBPF 程序按流对维护 Earliest
Departure Time 令牌，为每个报文盖离场时戳，由 fq qdisc 执行（成熟的
delay-only 整形路径，零拷贝、零丢包）。发送端代理经一跳 UDP 桥把速率
写进 BPF map（稳态数十微秒），控制环形态与 RDMA 侧完全一致，仅执行点
不同。包间隔超过 40 µs 的稀疏流旁路共享 pacing——时延敏感的小流不为
吞吐流的整形付排队税。把 TCP 执行面放在 host 而非 DPU 是明确的架构
结论（DPU 侧 TCP 卸载的负结论见 `docs/archive/superseded-designs.md`）。

## 6 参数

参数结构服从三条整定原则：**参数都是墙钟量**（速率常数以 s⁻¹ 计、
积分量以 bit 计，与控制周期无关，改周期不需重调，§4.2）；**积分量不随周期缩放**
（$V$ 是墙钟积分，§3.3）；**公平优先于利用率**（拿比例换利用率的选项
一律不取，双类并发约 87% 的合计利用率源于租户 TCP 自身丢包恢复的空窗，
账本侧无法买回）。生产值（真值以 `lab-registry.json` 的 `e_params`
段为准，已于 2026-07-27 随实现迁移改成下表值）：

| 参数 | 值 | 作用 |
|---|---|---|
| $T$ | 1 ms | 控制周期；环路总滞后 ≈ 1–2 $T$ |
| $k$ | 20 s⁻¹ | 跟踪带宽（时间常数 50 ms；陈旧性预算 $k\tau_{\rm eff} \lesssim 0.4$） |
| $\gamma$ | 0.25 | 审计折扣上限（目标最低 $(1-\gamma)\hat e_f$；阻尼 $\zeta = \tfrac12\sqrt{kV/(\gamma\hat e_f)}$） |
| $\delta$ | 0.15 | 需求增长余量（零和税，只能小，§3.2） |
| $\theta_b$ | 0.5 | 积压判别阈（占纯权重份额之比，§3.2） |
| headroom | 3% | 账本容量对物理容量的让位 |
| $V$ | 600 Mbit（= 0.1 s × 线速 × headroom） | 标记满刻度；积分上限 = $V$ |
| $N_1$, $N_2$ | 0.25 s, 2 s | fail-open 冻结 / 斜坡门限 |
| pace 地板 | 50 Mbps | 执行下限，防执行器深瘫 |

## 7 实现概况

| 组件 | 运行位置 | 形态 |
|---|---|---|
| rx 代理（测量·分配·标记·遥测） | 接收端 DPU Arm | Python，单进程 1 ms 循环 |
| vport 采样器（类级硬件计数直读） | 接收端 DPU Arm | C，共享内存发布 |
| tx 代理（响应律·发送端树·执行分发） | 发送端 DPU Arm | Python |
| RDMA 执行器（流对水位控制） | 发送端 DPU DPA | DOCA PCC device C |
| TCP 执行器（EDT pacing）+ 桥 | 发送端 host | tc eBPF + Python |

控制面合计约 1800 行 Python（v2 迁移删掉了 v1 律的三条骨架与配套钳位，
净减约 300 行），执行面约 1100 行 DPA C 与 250 行 eBPF C。
政策与参数的唯一真值是 registry 配置文件（repo 副本为准，接收端按文件
mtime 热加载政策段）。1 ms 周期下两端代理各占单核 < 9%，调度一遍
448 µs（20 流集合），舒适规模数百流集合。代码地图见
`hpft-implementation/README.md`；平台缺陷与实验卫生见 `ops_notes.md`。

## 8 性质

### 8.1 均衡分配 = 政策份额

单个受控资源上这是"按超额差分标记的 AQM + 各源响应律"的经典设定：
超出 $e_f$ 的流集合被审计折扣持续压回；低于 $\hat e_f$ 的解标、目标
回升；均衡点 $r_f \approx e_f$，而 water-filling 保证 $e_f$ 等于层级
加权 max-min 份额。借用场景不需要额外机制：空闲类需求小 → 其份额被
work-conserving 回灌进另一类的 $e_f$ → 借用类的目标无折扣地涨上去；
需求回归时份额重划、下移的目标把借用者拉回。多瓶颈下"最紧瓶颈生效"由
$pace = \min(R, Tree)$ 给出：每个瓶颈独立裁定、执行取最小，紧约束自动
生效，无需比较两端权重。

### 8.2 稳定性

主环（跟踪）是一阶低通：无条件稳定、结构性无过冲、无参数悬崖。审计环
（账本积分 + 折扣）线性化后是标准二阶系统，阻尼比
$\zeta = \tfrac12\sqrt{kV/(\gamma\hat e_f)}$ 可整定（§4.2），折扣有界使
残余振荡被限制在 $[(1-\gamma)\hat e_f,\ \hat e_f]$ 带内。两处诚实的
软肋：其一，跟踪律没有自带的公平安全网——正确性依赖接收端裁定（份额
与审计）的质量，目标失真它不会自我纠正，因此测量精度与 fail-open 是
关键路径而非可选件（§3.1、§4.4）；其二，$k\tau_{\rm eff}$ 陈旧性预算与
$\zeta$ 的份额依赖给出了解析的稳定边界（`design_theory.md`），但生产
参数点的实测裕度尚未系统测定。

### 8.3 实测定数

下表为 **v1 过渡形态（MIMD 律 + 执行面降速斜坡）** 上的实测数字，
出处见 `evaluation_index.md` 与各 `results/*/summary.md`。v2 在公平、
测量、fail-open、开销四个维度机制未变、预期不变；收敛维度因换律并
去掉降速斜坡而改变，理论预测（上升 ~130 ms、下降 ~150 ms，两向对称）
与重验证计划见 `design_theory.md`：

| 维度 | 结果 |
|---|---|
| 阶跃收敛（20G↔10G，竞争者离开/加入） | 上升 ~59 ms；下降 ~580 ms |
| incast 对称公平（8 流持续竞争） | Jain 0.999–1.000 |
| 测量精度 | 与主机计数逐字节对账一致；incast 稳态误差 0.36% |
| 遥测 | 带内往返 0.1 ms；每流集合每周期一条定长记录 |
| fail-open 时序 | 断流 0.25 s 冻结，2 s 进入斜坡，恢复后 1 s 内重新受控 |
| 控制面开销 | 两端代理单核 < 9%；调度单遍 448 µs @ 20 流集合 |

## 9 边界与扩展

**核心网瓶颈（§1.3 不保证项）的扩展路径**：核心网的真实 CE/RTT 信号
没有政策刻度，该处应改用带权重的响应律（权重 = 运营商配置），与边缘
的合成标记天然分离——合成标记走遥测通道、fabric 信号走实测。机制成立
但不在本测试床评估范围内（详见 `archive/rd_fairness_design_c.md` §4）。

**具名配置模式**：需求侧"份额保底"（账面份额永不缩水，代价是杀死
掉坑期间的临时借用）与按类步长（利用率优先，代价是比例漂移）作为具名
模式保留给特定 SLA 场景，均非默认（取舍数据见 `docs/archive/`）。

**已知局限**：亚控制周期的突发精度不承诺（租户 CC 兜底）；政策在线
变更以周期为粒度生效，无原子多瓶颈切换；VM 迁移适配、多接收端属主的
规模验证（当前测试床单发单收 8 VF）留作后续。

**计划中的组件**：三个已立项的扩展详见 `planned_extensions.md`——
①第三标记属主与多属主组合实证（把 §2.1 的"逐瓶颈独立记账、执行取最小"
从声明变成实测）；②对抗性租户分析（把策略性流量能从需求估计与 VQ 规则
中榨取的最坏超额量化为有界结论，加固 §8.2 承认的软肋）；③在线政策
重编程（运行中改权重/上限、以阶跃响应速度收敛，政策成为活的控制输入）。
