# 计划中的三个组件（2026-07-23 立项，均未开工）

来历：与 EyeQ（NSDI'13）的对位分析（结论已收进 `design.md` §2.4）暴露出
三件值得做的事——把 §2.1 的多属主组合从声明变成实测；把 §8.2 承认的
"正确性依赖标记质量"变成面对策略性租户的有界结论；把政策从静态配置
变成有实测收敛数字的活输入。本文档按"动机 → 设计 → 实验 → 验收 →
成本与风险"给出每个组件的详细方案，建议实施顺序见 §4。

## 1 多属主组合实证

**动机。** `design.md` §2.1 声称：一条流途经的每个瓶颈独立记账、独立
表达约束，执行取最小，最紧的瓶颈自动生效。但现行系统只有两个约束源
——发送端本地树（$Tree_f$，不经遥测）与接收端标记（经遥测）。"任意
多个**标记**属主经同一条律组合"这一结构性主张从未被实测过，而它恰是
单标量反馈骨架（EyeQ 式：每个接收端点向所有发送方广播同一个速率）给
不出的性质——那种骨架里没有"第二个标记源"的位置。做成实验，组合性
就从设计声明变成可引用的结果。

**设计。** 引入第三个标记属主：**聚合资源属主**，拥有一个两端主机都
不拥有的瓶颈。lab 里最自然的化身是"运营商级聚合上限"——例如"到接收
端主机的全部 RDMA 合计不得超过 Y"（模拟 ToR 上行口或运营商类配额）。
实现为一个独立进程（跑在任一 DPU 上，它只需要看到自己资源上的流量
计数），复用 rx_agent 的三个现成部件：逐流集合计数（vport/megaflow
链）、water-filling（对它的资源与它可见的流集合算自己的 $e'$、
$\hat e'$）、VQ 标记与遥测发送（同一线格式，用源 ID 字段或独立 UDP
端口区分来源）。

发送端 tx_agent 增加**多源合并**——这是本组件唯一的真正设计点，也是
"多属主、一条律"的显式化，论文可直接呈现为组合定则：

- 每流集合按源缓存最近一条记录 $\{s, \hat e, \text{新鲜度}\}$；
- 有效标记 $s_{\text{eff}} = \max_{\text{源}}(s)$——任何一个属主在响就得退；
- 有效设定点 $\hat e_{\text{eff}} = \min_{\text{源}}(\hat e)$——最紧属主的
  天花板生效（MI 硬顶与 MD 硬底都取它）；
- 新鲜度逐源独立跟踪：某源断流走**该源自己的** fail-open（把该源从
  max/min 中摘除并按 §4.4 时序冻结/回升），其余源照常——不能因一个
  属主故障而放开全部约束。

**实验。** 场景：单流集合（vf0 RDMA），三个约束源的上限各自可调
（发送端 MaxRate / 接收端政策 / 聚合上限 Y）。
(i) 静态三态：轮流让每个源成为最紧（如 20/10/15G 的三种排列），验证
稳态速率始终等于三者之 min；
(ii) 动态易主：运行中阶跃改某个源的上限使"谁最紧"换人，测切换收敛；
(iii) 近平局压力位：两个源上限只差 <3%，持续 60 s，验证不出现在两个
约束之间的持续振荡；
(iv) 多流版本：4 对 RDMA 同时受聚合上限约束，验证聚合短缺按
water-filling 权重摊进各流集合。

**验收。** 稳态 = 当前最紧裁定 ±10%；易主切换收敛与单属主阶跃同档
（上升 ~59 ms / 下降 ~0.6 s 量级）；近平局无持续振荡（允许靠换源迟滞
达标）；多流短缺分摊比例 = 权重比 ±10%。

**成本与风险。** 属主 daemon 是 rx_agent 的裁剪复用，tx 侧多源状态是
本体改动，合计天级。风险两处：近平局时 $\hat e_{\text{eff}}$ 在两源间
抖动（预案：换源迟滞，新源需低 3% 才接管）；多源 fail-open 语义要逐源
摘除而非全局放开，容易写错，需单独用例覆盖。

## 2 对抗性租户：需求估计与 VQ 的博弈加固

**动机。** §8.2 承认 MIMD 的正确性依赖标记质量；标记质量的上游是需求
估计（§3.2）与 VQ 规则（§3.3），两处都有租户可操纵的旋钮。现有对抗性
验证只有开流数博弈（1024 QP 逃逸，已由聚合水位修复）。EyeQ 一系只需
防"不响应的流量"（UDP）；本设计政策语义更丰富，攻击面也更丰富——
应当把"策略性租户最多能多拿多少"做成有界结论。这是三个组件里论文
防御价值最高的一个。

**攻击面清单**（按怀疑程度排序，前两个最像真洞）：

(a) **空闲速清赦免。** §3.3 规则：$r_f = 0$ 的周期 VQ 按每周期 $V$
速清。攻击者以"猛发 k 个周期、静默 1 个周期"循环——每次静默把全部
欠账一拍清零，标记从积不到有效剂量，时间平均速率可能显著超过 $e_f$。
速清是为 fail-open 精神设的善意规则，但它无条件、一拍生效，这就是可
利用点。候选加固（按侵入性排序）：连续 $m$ 个空闲周期才触发速清
（$m \approx 5$–$10$，把攻击者的静默成本乘 $m$ 倍）；空闲排空按
$\hat e_f$ 速率而非 $V/T$（与非空闲排空对齐，代价是真空闲流解标变慢）；
速清只赦免部分欠账（保留跨空闲期的"前科"折扣）。

(b) **churn 重放乐观起步。** 新流集合以 $R = Tree_f$ 起步（§4.2 乐观
起步），靠 1–2 周期的标记到达加约 0.6 s 的下降收敛压回。攻击者刻意
静默到状态被遗忘（VQ 清零、流状态过期），再以满 $Tree_f$ 突发，如此
循环——每圈白拿约一个下降收敛窗的超额，超额率约
$(Tree - e)\cdot t_{\text{conv}} / (t_{\text{conv}} + t_{\text{idle}})$，
攻击者会把 $t_{\text{idle}}$ 压到遗忘阈值。候选加固：流集合状态保留期
拉长；重现的流集合以 $\min(Tree,\ \text{上次稳态 } R\,(1+\delta))$ 起步
——乐观起步只给真正的新流，回头客按前科。注意保留期须远大于正常请求
间隔，避免误伤正常短流。

(c) **backlog 判别欺骗。** §3.2 的积压判别 $r \ge \theta_b\,\hat s$ 是
瞬时的。ON/OFF 占空比恰好使测量窗内过阈的攻击者，以"积压"身份占住
完整加权份额、实际平均用量远低——伤害是兄弟类借不到它让不出的容量
（利用率攻击，损人不利己型）。量化利用率损失上界；加固候选：判别改
滑窗均值。

(d) **δ 余量棘轮。** 理论上界就是 $\delta$（15%），实测验证逼近程度
即可，预期无需加固。

(e) **稀疏流旁路滥用**（TCP 执行面）。包间隔 >40 µs 的流绕过共享
pacing（§5.3）；攻击者把 bulk 拆成大量恰好稀疏的流聚合逃逸。单流上限
≈ MTU/40 µs ≈ 0.3G，N 条并发即 N × 0.3G。量化实际可达聚合逃逸带宽；
加固候选：稀疏旁路加 per-vnic 聚合预算，超预算的稀疏流回到共享 pacing。

(f) **阳性对照：开流数博弈。** 1024 QP 场景重跑，应保持免疫（聚合
水位，§5.2）。

**实验。** 参数化攻击流生成器（占空比、周期、相位、突发长度可扫），
每类攻击输出三个数：攻击者超额率（时间平均实得 / 应得）、受害流份额
损失、合计利用率损失。先在现行参数下量化基线漏洞大小，再逐个上加固
重测；全程带正常负载回归（等价于 m1 / m2 / incast8 的场景），确认
加固不伤良民。

**验收。** 每类攻击的最坏超额压到有界小量（目标量级 ≤ δ + headroom
≈ 18%，理想 <10%）；加固后正常场景回归无退化（收敛时间、Jain、
利用率均在现有带内）。

**成本与风险。** 三个组件里最重：生成器 + 六类攻击 × 扫描 + 可能的
规则修订。若 (a)(b) 证实为真洞，改的是 §3.3/§4.2 的规则，属设计修订，
须全量回归。固有张力：速清与乐观起步都是 fail-open 精神的善意规则，
加固要在"不冤枉良民"与"不便宜坏人"之间找参数，可能出现没有免费
午餐的权衡——那本身也是可写进论文的结论。

## 3 在线政策重编程

**动机。** 保证型系统（EyeQ 一系）的带宽保证是 provision-time 的：改
保证要走放置/准入流程。本设计的账本每周期重算，政策天然是活的控制
输入——但从未被当成特性对待：`design.md` §9 把政策变更列在已知局限，
tx_agent 目前只在启动时读一次政策（现状缺口）。补成受支持的操作并给出
实测收敛数字，就得到一个骨架同源系统给不出的能力演示：**政策变更以
阶跃响应的速度生效**。预期就是阶跃档（上 ~59 ms / 下 ~0.6 s）：账本
在变更后的下一个周期即重划份额，其余时间全是律在跟踪新设定点。

**设计。** 三小件：

- **tx_agent 政策热载**：与 rx_agent 相同的 mtime 检测（rx 已有、tx
  缺）；
- **push 工具**：改 repo registry → scp 下发两台 DPU → `mv` 原子替换
  （遵守"repo 副本唯一真值"纪律）；同一文件内多键变更天然同 tick
  生效；工具内置两侧联动检查（ops_notes 陷阱：改 cap 必须 {src, dst}
  两侧一起改）；
- **生效偏差的界定**：跨主机生效偏差 = 下发时延 + 各自慢环检测周期
  （rx 慢环 200 ms），实测并报告。不追求跨机原子性（§9 已知局限维持），
  但把偏差从"未知"变成"有界已测"。

**实验。**
(i) 饱和双类负载下类权重 1:1 → 3:1 → 1:1：测新比例进带周期数、过渡期
逐周期 Jain、过渡窗内丢包/ECN 证据（应为零——政策变更不应制造物理
拥塞，headroom + MD 应吸收）；
(ii) MaxRate 阶跃（两侧联动，上调与下调各一）；
(iii) 4 发送方 incast 下 per-sender 权重 $u$ 变更；
(iv) 变更频率扫描：每 5 s → 1 s → 0.5 s → 0.1 s 交替翻转权重，找出系统
能干净跟踪的政策变更频率上限（预期受下降收敛 ~0.6 s 限制，约 1 Hz 档）。

**验收。** 权重类变更：新份额进 ±10% 带的时间 ≤ 阶跃响应同档（显著
更慢即存在未知滞后，要查）；全过渡无丢包证据；跨机生效偏差 < 300 ms
（下发 + 慢环）且有实测数。

**成本与风险。** 三件里最轻：tx 热载几十行、push 工具一个脚本、实验
半天到一天。风险几乎只有一个：热载瞬间本地政策与在途遥测的 $\hat e$
短暂不一致（一拍级），预期由律的双向钳位自然吸收，实验中确认即可。

## 4 建议顺序

**3 → 1 → 2**。组件 3 最便宜、demo 价值高，先做；组件 1 把结构性主张
落地，涉及 tx 多源合并的真设计，其次；组件 2 工作量最大，但把 §8.2 的
软肋变成有界结论，论文防御价值最高，放最后集中做。1 与 3 无依赖，可
并行。
